# Purpose

This document defines the conceptual model used by Ambient Physical AI to represent contextual information.

The project adopts the classical **5 Ws** model from Context-Aware Computing as the internal semantic representation of environmental context.

Rather than treating context as a collection of unrelated sensor values, Ambient Physical AI organizes information according to five fundamental questions:

```text
Who?
Where?
When?
What?
Why?
```

These questions become the semantic foundation of the Context Builder and the Cognitive Runtime.

---

# Background

One of the fundamental ideas of Context-Aware Computing is that intelligent environments should not simply react to sensor values.

Instead, they should understand the meaning of what is happening.

The Ambient Physical AI project adopts this philosophy.

Sensors observe the physical world.

The Cognitive Runtime transforms observations into semantic knowledge.

---

# Inspiration

The concepts presented here are inspired by the evolution of Context-Aware Computing and Ubiquitous Computing, where the environment becomes capable of perceiving people, situations and intentions.

Within Ambient Physical AI, these concepts are organized using the classical 5 Ws model.

---

# The Five Ws

The five questions are used as the semantic dimensions of every Context Package generated by the Cognitive Runtime.

---

# WHO

## Question

```text
Who is involved?
```

Represents the identity of the people currently interacting with the environment.

Examples:

```text
Professor

Student

Visitor

Researcher

Technician
```

Current implementation:

```text
Identity Node
(M5Dial + NFC)
```

Current information:

```text
User ID

Name

Role

Preferences (future)

Accessibility profile (future)
```

Example:

```json
{
  "id":"claudio",
  "name":"Claudio",
  "role":"owner"
}
```

---

# WHERE

## Question

```text
Where is the interaction occurring?
```

Represents the physical or logical location of the interaction.

Examples:

```text
Laboratory

Meeting Room

Classroom

Office

Home
```

Future sources:

```text
Presence Layer

Indoor positioning

Room configuration

Environmental sensors
```

Example:

```json
{
    "environment":"Lab"
}
```

---

# WHEN

## Question

```text
When is it happening?
```

Represents the temporal context.

Examples:

```text
Timestamp

Morning

Night

Weekend

Class Schedule

Deadline proximity
```

Future implementation:

```text
AX630C Runtime

System Clock

Calendar Integration
```

Example:

```json
{
    "timestamp":"2026-06-24T19:30:00"
}
```

---

# WHAT

## Question

```text
What is currently happening?
```

Represents the activity being performed.

Examples:

```text
Laboratory Experiment

Teaching

Meeting

Project Discussion

Presentation

Maintenance
```

This information is not directly measured by sensors.

It is inferred by the Context Builder.

Example:

```json
{
    "activity":"Project Discussion"
}
```

---

# WHY

## Question

```text
Why is this happening?
```

Represents the inferred intention or purpose of the current activity.

Unlike the previous dimensions, this information usually cannot be measured directly.

It emerges from cognitive interpretation.

Examples:

```text
Teaching

Learning

Research

Collaboration

Maintenance

Demonstration
```

Future implementation:

```text
Semantic reasoning

Historical context

User preferences

LLM support
```

Example:

```json
{
    "intent":"Develop Ambient Physical AI"
}
```

# Context Builder

The Context Builder is responsible for integrating information collected from multiple layers of the ecosystem.

Conceptually:

```text
Presence Layer
        │
        ▼
Identity Layer
        │
        ▼
Environment Sensors
        │
        ▼
Temporal Information
        │
        ▼
Context Builder
        │
        ▼
5 Ws
        │
        ▼
Context Package
```

The Context Builder does not merely aggregate data.

It organizes information into a semantic representation.

---

# Context Package

The Context Package represents the current understanding of the environment.

Example:

```json
{
  "who": {
    "id": "claudio",
    "role": "owner"
  },
  "where": {
    "environment": "Lab"
  },
  "when": {
    "timestamp": "2026-06-24T19:30:00"
  },
  "what": {
    "activity": "Project Discussion"
  },
  "why": {
    "intent": "Develop Ambient Physical AI"
  }
}
```

This package becomes the semantic representation of the environment.

# Relationship with MCP

The Cognitive Runtime should expose semantic services rather than raw sensor values.

Examples:

```text
GetCurrentIdentity()

GetPresenceState()

GetEnvironmentContext()

GetCurrentActivity()

GetCurrentIntent()
```

These services are natural projections of the 5 Ws model.

Instead of exposing implementation details, the runtime exposes meaning.

---

# Relationship with StackChan

StackChan should not receive low-level events.

Instead, it should consume semantic knowledge.

The interaction becomes:

```text
Identity Package
        │
        ▼
Context Builder
        │
        ▼
5 Ws Context Package
        │
        ▼
Semantic MCP Services
        │
        ▼
StackChan
```

This allows StackChan to understand the situation rather than merely reacting to commands.

# Guiding Principle

The Ambient Physical AI ecosystem is not designed to react to isolated sensor readings.

It is designed to understand situations.

The 5 Ws provide the semantic structure through which the environment transforms physical events into contextual knowledge.

This contextual knowledge becomes the basis for reasoning, interaction and autonomous adaptation.
