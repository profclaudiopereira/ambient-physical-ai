# Overview

The **Runtime State RGB Node** is the dedicated **Runtime State Indicator** of the Ambient Physical AI Expression Layer and is now implemented on the **M5StickS3** platform.

Its responsibility is to translate normalized Cognitive Runtime states into synchronized visual feedback presented through the integrated M5StickC Plus 2 display and an external WS2812 RGB LED bar.

Unlike the Ambient Lighting nodes, this firmware does **not** represent environmental transformation. Instead, it provides an immediate and intuitive visualization of the internal execution state of the distributed Cognitive Runtime, allowing nearby users to understand what the system is currently doing.

The firmware is intentionally focused on presentation. It performs no reasoning, semantic interpretation, authorization, context generation or AI inference.

All Runtime States are generated by the Cognitive Runtime and delivered through a dedicated UDP Runtime State channel.

```text
                Cognitive Runtime
                        │
                Runtime State UDP
                        │
                        ▼
             Runtime State RGB Node
                        │
        Runtime State Visualization
                        │
           Display + WS2812 RGB LEDs
```

# Expression Layer Architecture

The Ambient Physical AI Expression Layer is composed of specialized visualization devices, each responsible for a different form of expression.

```text
Expression Layer

│

├── Voice Expression
│       Echo Pyramid
│
├── Cognitive Status
│       Runtime State RGB Node
│
└── Ambient Lighting
        ├── Atom Matrix RGB Node
        └── RGB Strip Node
```

Each node has a single responsibility.

The Runtime State RGB Node is exclusively responsible for **Cognitive Status Visualization**.

Ambient Lighting nodes remain responsible for representing environmental transformations generated by Semantic Events.

This architectural separation intentionally prevents Runtime State visualization from being confused with ambient expression.

---

# Mission

Provide deterministic, synchronized and immediately understandable visualization of the Cognitive Runtime execution state.

The node continuously receives normalized Runtime State notifications generated by the Cognitive Runtime and converts them into consistent visual feedback by synchronizing:

- integrated display background;
- Runtime State label;
- external WS2812 RGB LED bar.

This visualization allows nearby users to understand the current execution stage of the distributed system without inspecting logs, consoles or diagnostic tools.

---

# Responsibilities

The Runtime State RGB Node is responsible for:

- displaying the current Cognitive Runtime state;
- synchronizing the display and WS2812 RGB LEDs;
- translating normalized Runtime States into visual presentation;
- providing deterministic visual timing through the Runtime State Scheduler;
- maintaining local presentation policies without affecting the Cognitive Runtime;
- presenting an intuitive interpretation of runtime execution;
- remaining fully independent from reasoning, semantic generation and AI inference.

The node intentionally does **not** perform:

- Large Language Model inference;
- semantic reasoning;
- authorization;
- context generation;
- environmental decision making;
- ambient lighting control.

# Design Principles

The firmware follows a strict separation of responsibilities.

Each software module owns one engineering responsibility only.

The implementation is organized so that:

- networking remains independent from presentation;
- Runtime State validation remains independent from hardware;
- visual mapping remains independent from display and LED drivers;
- hardware control remains isolated from Cognitive Runtime semantics.

This modular organization improves maintainability, simplifies testing and preserves architectural scalability as new Runtime States are introduced.

---

# Software Architecture

The Runtime State RGB Node follows a layered architecture that separates networking, Runtime State processing, visual mapping and hardware control.

Each layer owns a single engineering responsibility, minimizing coupling between software components and simplifying future maintenance.

```text
                Cognitive Runtime (AX630C)
                          │
                   Runtime State UDP
                          │
                          ▼
                semantic_receiver.c
                          │
                          ▼
                semantic_consumer.c
         (Validation + Queue + Scheduler)
                          │
                          ▼
             expression_processor.c
        (Normalized Runtime Vocabulary)
                          │
                          ▼
                  rgb_effects.c
             (Visual Mapping Layer)
                          │
                          ▼
                rgb_controller.cpp
       (Hardware Presentation Boundary)
                 ┌──────────┴──────────┐
                 ▼                     ▼
          StickC Display        WS2812 RGB LEDs
```

This layered organization isolates Cognitive Runtime semantics from the physical hardware while keeping each software module focused on a single responsibility.

# Runtime State Contract

The StickC Plus 2 Runtime State Indicator listens for normalized Runtime State messages.

Current message contract:

```json
{
  "type": "runtime_state",
  "target": "runtime_state_indicator",
  "state": "thinking"
}
```

Default UDP port:

```text
5555
```

Only messages matching the Runtime State contract and addressed to the Runtime State Indicator are accepted.

Unsupported message types or targets are safely ignored.

# Runtime State Scheduler

The StickC Plus 2 Runtime State Indicator implements an asynchronous presentation scheduler to ensure that important Cognitive Runtime states remain visible long enough to be perceived by nearby users.

Rather than presenting Runtime States immediately after packet reception, accepted messages are placed into a local queue and processed sequentially by a dedicated worker task.

```text
Runtime State Packet
          │
          ▼
JSON Validation
          │
          ▼
Runtime State Queue
          │
          ▼
Presentation Worker
          │
          ▼
Expression Processor
          │
          ▼
Visual Presentation
```

This architecture provides deterministic visualization while keeping network communication completely independent from presentation timing.

The scheduler affects only the local visualization performed by the StickC Plus 2 Runtime State Indicator.

It never delays:

- Cognitive Runtime execution;
- Semantic Event generation;
- Runtime State publication;
- UDP packet reception;
- other Expression Layer nodes.

---

# Runtime State Presentation Policy

Some Runtime States represent very short execution stages.

Without presentation scheduling these states could disappear before users have enough time to recognize them.

To improve readability, the firmware applies minimum presentation times to selected Runtime States.

| Runtime State | Minimum Presentation |
|---------------|---------------------:|
| thinking | 500 ms |
| responding | 800 ms |
| alert | 1500 ms |
| error | 1500 ms |
| others | immediate |

These timings are local presentation policies only.

They do not introduce latency into the Cognitive Runtime or any network communication.

---

# Runtime State Validation

Every received packet is validated before entering the presentation queue.

The consumer verifies:

- JSON syntax;
- message type;
- Runtime State field;
- destination target;
- Runtime State name length;
- queue availability.

Only valid Runtime State messages addressed to the Runtime State Indicator are accepted.

Messages intended for other Expression Layer devices are ignored without affecting firmware stability.

# Accessibility Considerations

The Runtime State Indicator is designed to maximize immediate visual comprehension.

The firmware improves readability by:

- synchronizing the display and RGB LEDs;
- presenting textual Runtime State labels;

These design decisions reduce ambiguity and improve usability under different lighting conditions.

# Engineering Decisions

Several engineering decisions guide the implementation.

## Dedicated Runtime State Pipeline

Runtime State visualization is intentionally independent from Semantic Event processing.

This separation prevents presentation timing from interfering with Cognitive Runtime execution while allowing specialized visualization policies for Runtime State indicators.

---

## Hardware Abstraction

Hardware-specific logic is fully isolated inside the RGB Controller.

Presentation modules never access:

- M5Unified APIs;
- GPIO assignments;
- WS2812 driver implementation;
- physical LED configuration.

This boundary significantly improves maintainability.

---

## Deterministic Presentation

Runtime State visualization is intentionally asynchronous.

Packet reception remains responsive while the Presentation Scheduler guarantees deterministic visual timing.

---

## Modular Software Architecture

Each software module owns one well-defined engineering responsibility.

This organization minimizes coupling, simplifies testing and supports future expansion without requiring architectural redesign.

# Engineering Notes

This firmware represents the validated Runtime State Indicator of the Ambient Physical AI Expression Layer.

Its architecture intentionally separates:

- Runtime State communication;
- Runtime State scheduling;
- Runtime State interpretation;
- visual mapping;
- hardware presentation.

This separation allows each layer to evolve independently while preserving the communication contract between the Cognitive Runtime and the Expression Layer.

The implementation also demonstrates an important architectural principle adopted throughout Ambient Physical AI:

> Higher software layers describe **what** should be presented.

> Lower software layers determine **how** that presentation reaches the physical world.

This principle minimizes coupling, simplifies maintenance and improves long-term scalability of the distributed cognitive ecosystem.
