# RGB Strip Node

> **Ambient Physical AI**  
> **Expression Layer — Ambient Lighting**

---

# Overview

The RGB Strip Node is a validated Expression Layer node responsible for transforming high-level semantic events into ambient lighting.

Unlike localized visual indicators or voice interfaces, this node uses a WS2812 LED strip as an environmental expression device, allowing the physical environment itself to communicate semantic information generated by the Ambient Physical AI ecosystem.

The firmware receives Semantic Events produced by the Cognitive Runtime and converts them into predefined lighting behaviors while preserving a modular software architecture and a clear separation between communication, semantic interpretation and hardware control.

The implementation has been validated using ESP-IDF and is integrated into the Ambient Physical AI distributed architecture.

# Purpose

The RGB Strip Node is responsible for expressing semantic information through ambient lighting.

It receives Semantic Events generated by the Cognitive Runtime and converts them into predefined RGB lighting effects suitable for the surrounding environment.

The firmware intentionally performs no cognitive processing.

Its responsibility begins only after a validated Semantic Event has been received.

---

# Responsibilities

The RGB Strip Node is responsible for:

- receiving Semantic Events over UDP;
- validating incoming semantic messages;
- extracting the semantic context when available;
- selecting the appropriate lighting behavior;
- applying predefined ambient lighting profiles;
- controlling the WS2812 LED strip.

The node operates as a semantic expression device and does not participate in higher-level cognitive decisions.

---

# What This Node Is Not

This firmware intentionally does **not** perform any of the following responsibilities:

- user authentication;
- identity management;
- sensor acquisition;
- context generation;
- AI inference;
- decision making;
- semantic reasoning;
- Cognitive Runtime coordination.

Those responsibilities belong to other layers of the Ambient Physical AI architecture.

# Internal Software Architecture

The RGB Strip Node follows a layered architecture where each software module has a single, well-defined responsibility.

Communication, semantic interpretation and hardware control remain isolated, reducing coupling and simplifying future maintenance.

```text
Wi-Fi Station
        │
        ▼
Semantic Receiver
        │
        ▼
Semantic Consumer
        │
        ▼
Expression Processor
        │
        ▼
RGB Effects
        │
        ▼
RGB Controller
        │
        ▼
ESP-IDF LED Strip Driver
        │
        ▼
WS2812 LED Strip
```

Module responsibilities:

| Module | Responsibility |
|---------|----------------|
| Wi-Fi Station | Network initialization and connectivity management |
| Semantic Receiver | Receives Semantic Events over UDP |
| Semantic Consumer | Validates JSON messages and extracts semantic information |
| Expression Processor | Selects the appropriate semantic lighting behavior |
| RGB Effects | Implements predefined lighting behaviors |
| RGB Controller | Controls the physical WS2812 LED strip |

This separation allows each module to evolve independently while preserving the communication contracts between layers.

# Semantic Context

The firmware supports an optional semantic context accompanying Semantic Events.

Rather than exposing JSON objects throughout the application, the Semantic Consumer converts the received information into a simplified internal structure before forwarding it to the Expression Processor.

Current validated information includes:

```text
user_id
```

This design intentionally decouples the Expression Layer from the network representation while allowing future semantic information to be incorporated without modifying the processing pipeline.

Examples of future context information may include:

- accessibility preferences;
- preferred brightness;
- preferred animations;
- environmental preferences.

These capabilities are planned but are **not** part of the current validated implementation.

---

# Supported Semantic Events

The following Semantic Events are currently implemented and validated.

| Semantic Event | Lighting Behavior |
|----------------|-------------------|
| `boot` | Neutral white during initialization |
| `idle` | Very soft blue |
| `presence_detected` | Soft yellow while awaiting authentication |
| `identity_authenticated` | Profile-aware ambient lighting |
| `processing` | Neutral white processing indication |
| `system_error` | Persistent low-intensity red |

All listed events are implemented in the current firmware.

Unsupported Semantic Events are safely rejected by the Expression Processor without affecting node stability.

---

# Profile-aware Ambient Lighting

Following successful authentication, the Cognitive Runtime may include the authenticated user identifier inside the Semantic Event.

The RGB Strip Node interprets this information locally and applies the corresponding ambient lighting profile.

Current validated profiles are:

| Profile | Ambient Lighting |
|---------|------------------|
| Claudio | Neutral-cool soft blue |
| Herminio | Warm amber |
| Mariana | Warm white |
| Student | Uses Mariana profile |
| Visitor | Soft cyan |
| Guest | Uses Visitor profile |

If an unknown profile is received, the firmware safely falls back to the Visitor lighting profile.

This behavior guarantees deterministic operation while preserving backward compatibility with older Semantic Events.

# Network Architecture

The node operates as a Wi-Fi Station within the Ambient Physical AI network.

Current validated network configuration:

```text
IPv4    : 192.168.77.26
Gateway : 192.168.77.1
Mask    : 255.255.255.0
```

The firmware uses a deterministic static IPv4 configuration instead of DHCP, simplifying deployment, packet tracing and distributed integration.

Automatic reconnection is performed whenever Wi-Fi connectivity is lost.

# Communication Contract

The RGB Strip Node consumes Semantic Events transported over UDP.

Current validated message structure:

```json
{
    "type":"semantic_event",
    "event":"identity_authenticated",
    "target":"rgb_strip",
    "payload":
    {
        "user_id":"claudio"
    }
}
```

The firmware accepts Semantic Events addressed to:

- `rgb_strip`
- `expression_layer`

Older Semantic Events that do not include the optional payload remain fully compatible with the current implementation.

# Engineering Principles

The implementation follows several engineering principles adopted throughout the Ambient Physical AI project.

## Separation of Responsibilities

Each software module performs one clearly defined task.

Network communication, semantic interpretation and hardware control remain isolated from one another.

---

## Low Coupling

Higher software layers remain independent from hardware-specific implementation.

The Expression Processor does not manipulate LEDs directly, while the RGB Controller remains unaware of Semantic Events.

---

## Deterministic Behavior

Every supported Semantic Event produces one predefined lighting behavior.

Unknown profiles fall back to the Visitor profile, ensuring predictable system behavior.

---

## Backward Compatibility

Profile-aware lighting extends the Semantic Event format using optional payload information.

Older Semantic Events remain fully supported without modification.

---

## Hardware Abstraction

All interaction with the WS2812 strip is encapsulated by the RGB Controller module.

This approach minimizes hardware dependencies throughout the remaining software architecture.

---

## Maintainability

The firmware architecture favors small, focused modules with explicit interfaces, simplifying maintenance and future evolution.
