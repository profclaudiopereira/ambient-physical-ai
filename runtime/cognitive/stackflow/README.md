# StackFlow Cognitive Runtime

## Ambient Physical AI

**Distributed Cognitive Ecosystem Powered by StackFlow**

## Overview

This directory contains the StackFlow Cognitive Runtime for the Ambient Physical AI project.

The Cognitive Runtime is the semantic coordination layer that receives validated physical events from the Identity Layer, transforms them into structured runtime context, stores the latest validated context, and exposes this context through local semantic services and MCP-compatible tool definitions.

The current implementation represents a stabilized engineering baseline for the Cognitive Runtime laboratory. It was developed incrementally through real hardware validation, beginning with UDP transport validation from the Identity Node and evolving into a semantic runtime pipeline with Context Builder, 5W Context Package, Context Registry, Local Semantic Services, and a Semantic MCP Tool Layer.

This README is the official technical documentation for the current StackFlow Cognitive Runtime subsystem.

It documents:

- the current runtime architecture;
- the validated execution pipeline;
- the implemented runtime components;
- the directory organization;
- the validation procedure;
- the validation evidence;
- the StackChan MCP investigation;
- the preserved laboratory artifacts;
- the current limitations and post-competition future work.

The goal of this subsystem is not to replace the Identity Node, the Ambient Runtime Node, or StackChan. Its role is to act as the semantic runtime layer between physical sensing, identity/context events, local cognitive services, and future ambient behavior.

---

## Current Runtime Architecture

The Cognitive Runtime currently operates as a Python-based runtime layer on the AX630C + LLM Mate node.

Its current responsibility is to receive an Identity Package generated by the Identity Node, convert it into a structured semantic Context Package, maintain the latest validated runtime context, and expose that context through local service functions and MCP-style tool mappings.

The current runtime does **not** yet perform:

- full StackFlow orchestration;
- local Qwen inference;
- decision engine execution;
- ambient runtime actions;
- MQTT integration;
- production StackChan context push.

Those capabilities belong to future milestones.

The current validated architecture is intentionally lightweight, reproducible, and focused on semantic correctness.

This pipeline separates physical transport from semantic runtime state.

The Identity Node is responsible for detecting and mapping the user identity. The Cognitive Runtime is responsible for transforming that validated event into a semantic representation that can be consumed by local services, MCP tools, and future cognitive runtime capabilities.

## Runtime Components

The Identity UDP Listener receives JSON Identity Packages from the Identity Node over UDP port `4444`.

It validates the transport path between:

```text
Identity Node V1
        │
        ▼
UDP 4444
        │
        ▼

```

The listener confirms:

- network connectivity;
- valid JSON reception;
- Identity Package delivery from the M5Dial Identity Node to the AX630C Cognitive Runtime Node.

```text
identity_udp_listener.py
```


### Context Builder

The Context Builder transforms a validated Identity Package into a semantic Context Package.

Earlier laboratory versions generated only a human-readable message, such as:

```text
Olá Claudio, bem-vindo ao laboratório.
Contexto: Lab.
```

The current responsibility of the Context Builder is broader and more structured. It now produces a 5W Context Package.

Primary file:

```text
context_builder.py
```

---

### 5W Context Package

The 5W Context Package is the first semantic representation produced by the Cognitive Runtime.

It follows the 5W Context Model:

```text
Who
Where
When
What
Why
```

Current implementation:

| Field | Current behavior |
| --- | --- |
| Who | Populated from the Identity Package profile. |
| Where | Populated from the environment context. |
| When | Generated by the Cognitive Runtime. |
| What | Represents the validated runtime activity. |
| Why | Reserved for future semantic reasoning. |

The Context Package is now the primary semantic object of the Ambient Physical AI Cognitive Runtime.

Human-readable messages remain available only for debugging and validation compatibility.

---

### Context Registry

The Context Registry stores the latest validated Context Package as the Current Runtime Context.

It introduces the concept of a single current semantic state for the runtime.

Primary file:

```text
context_registry.py
```

Responsibilities:

- store the latest validated Context Package;
- replace the current context whenever a new validated Identity Package is received;
- provide a single semantic source for future Cognitive Runtime services;
- decouple semantic knowledge from transport and hardware events.

The Context Registry is intentionally lightweight. It stores only the latest validated semantic state.

Future MCP services should consume this runtime context instead of accessing hardware components directly.

---

### Local Semantic Services

Local Semantic Services expose stable service functions over the Current Runtime Context.

These services are not MCP tools by themselves. They are local runtime interfaces that future MCP tools can reuse without depending directly on transport, UDP packets, or hardware-specific details.

Primary file:

```text
semantic_services.py
```

Validated services:

```text
get_runtime_status()
get_current_identity()
get_current_environment()
get_current_activity()
```

---

### Semantic MCP Tool Layer

The Semantic MCP Tool Layer maps local semantic services to MCP-compatible tool definitions and tool calls.

This layer does not yet implement WebSocket transport. It provides a tool abstraction over the validated local semantic services.

Primary file:

```text
semantic_mcp_tools.py
```

Validated tools:

```text
get_runtime_status
get_current_identity
get_current_environment
get_current_activity
get_current_context
```

This layer prepares the Cognitive Runtime for future integration with MCP-based consumers such as StackChan/XiaoZhi, while keeping the current implementation local, testable, and independent from production MCP transport.

---

### StackChan Notifier Prototype

The StackChan notifier prototype was implemented during the early integration phase.

Primary file:

```text
stackchan_notifier.py
```

Status:

```text
Prototype implemented
```

Direct StackChan delivery was suspended after the MCP architecture discovery. The validated path forward is not direct message injection, but MCP Tool Provider integration.

## Identity Package

The Identity Package is generated by the Identity Node V1 running on the M5Dial.

It represents a validated identity event and is transmitted to the Cognitive Runtime Node as JSON over UDP.

Example payload:

```json
{
  "type": "identity_package",
  "profile": {
    "id": "claudio",
    "name": "Claudio",
    "role": "owner"
  },
  "context": "Lab",
  "nfc": {
    "detected": true,
    "card_present": true,
    "uid": "8804DC32"
  },
  "source": "m5dial_identity_console_v1"
}
```

The Identity Package currently provides the main physical event input to the Cognitive Runtime.

## StackChan MCP Investigation Summary

The StackChan investigation changed the integration strategy.

The initial assumption was that the Cognitive Runtime might send direct notifications to StackChan. The laboratory showed that StackChan appears to be integrated through a broader XiaoZhi/StackChan ecosystem involving personality, memory, MCP, and LLM orchestration.

Therefore, the safer and more extensible integration model is:

```text
Cognitive Runtime
        │
        ▼
Semantic MCP Tool Provider
        │
        ▼
XiaoZhi MCP Broker
        │
        ▼
StackChan / LLM interaction
```

Validated result:

```text
AX630C Cognitive Runtime can expose an MCP tool.
StackChan can request that tool through the XiaoZhi MCP Broker.
The returned semantic value can influence the StackChan response.
```

Current limitation:

```text
Context Push was not validated.
```

This means the current validated path is tool-based semantic retrieval, not unsolicited runtime context injection.

Confirm that the M5Dial is connected to the expected local network.

```cpp
#define AX630C_IP "192.168.77.15"
```

- investigation of Context Push;

- richer Context Registry persistence;

## Engineering Principles

The Cognitive Runtime follows these engineering principles:

- preserve validated technical evidence;
- separate hardware transport from semantic runtime state;
- keep the current runtime lightweight and reproducible;
- avoid coupling MCP tools directly to hardware events;
- expose semantic services through stable local interfaces;
- preserve laboratory artifacts for reproducibility;
- avoid claiming unvalidated capabilities;
- treat StackChan integration as MCP-based unless future evidence proves otherwise;
- keep post-competition features separate from the validated runtime baseline.
