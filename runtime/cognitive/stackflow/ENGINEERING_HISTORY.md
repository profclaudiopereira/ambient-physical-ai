## Runtime Requirements

### Hardware

The validated integration environment includes:

* AX630C + LLM Mate;
* M5Dial Identity Node;
* WS1850S NFC interface;
* Tab5 Ambient Runtime;
* Echo Pyramid Voice Node;
* Runtime and Expression Layer indicators;
* local IPv4 network.

Not every external node is required to start the Cognitive Runtime, but unavailable adapters may report delivery failures during execution.

### Software

The validated Cognitive Runtime environment uses:

* Ubuntu 22.04 LTS on the AX630C;
* Python 3.10 or later;
* the Ambient Physical AI repository;
* network configuration appropriate to the current deployment.

## Starting the Runtime

From the repository root:

```bash
cd runtime/cognitive/stackflow
python3 identity_udp_listener.py
```

The current entry point starts:

* UDP ingress on port `4444`;
* Context Registry integration;
* Semantic Event generation;
* Semantic Dispatcher and registered adapters;
* Runtime State publication;
* the StackChan MCP server in a background thread.

Representative startup information includes:

```text
AX630C Identity and Context UDP Listener
Listening on 0.0.0.0:4444
Identity Package ingress: ENABLED
Context Change Request ingress: ENABLED
Cognitive Context Builder: ENABLED
Semantic Event Generator: ENABLED
Semantic Dispatcher: ENABLED
Shared Context Registry: ENABLED
```

Actual adapter destinations depend on deployment environment variables and the addresses configured in the current source baseline.

## Runtime Ingress Validation

The runtime currently accepts two UDP ingress contracts:

```text
identity_package

context_change_request
```

An Identity Package starts the authentication-oriented semantic flow.

A Context Change Request updates the active environment while preserving the already validated identity and authorization state.

## Identity Package Example

The following payload represents the original validated Identity Layer contract used during integration:

```json
{
  "type": "identity_package",
  "profile": {
    "id": "claudio",
    "name": "Claudio",
    "role": "owner"
  },
  "context": "Lab",
  "nfc": {
    "detected": true,
    "card_present": true,
    "uid": "8804DC32"
  },
  "source": "m5dial_identity_console_v1"
}
```

Current producers may also provide `current_context`. The Context Builder retains compatibility with the earlier `context` field.

## Context Registry Validation

The Context Registry was validated by alternating authenticated profiles.

```text
Student
        │
        ▼
Current Runtime Context = Student

Claudio
        │
        ▼
Current Runtime Context = Claudio

Student
        │
        ▼
Current Runtime Context = Student
```

This validation demonstrated that:

* the latest Context Package replaces the previous state;
* semantic services observe the updated runtime context;
* the runtime does not retain multiple active identity contexts;
* state replacement occurs independently from the original transport payload.

## Basic Troubleshooting

### No UDP packets received

Confirm that the runtime is listening on port `4444`:

```bash
ss -lunp | grep 4444
```

Verify network reachability between the producing node and the AX630C.

### Unsupported packet type

The ingress currently accepts:

```text
identity_package
context_change_request
```

Other values are rejected by the listener.

### Context change rejected

A Context Change Request requires an active authenticated context in the Context Registry.

Authenticate a profile before requesting an environment change.

### Adapter delivery failure

A failed external adapter does not necessarily indicate failure of the semantic pipeline.

Inspect the dispatch result for each registered target independently:

```text
stackchan
rgb_strip
ambient_runtime
echo_pyramid
```

### Runtime State indicator unavailable

Runtime State delivery is observational.

Failure of the dedicated indicator must not prevent Context Package creation, Registry updates or Semantic Event dispatch.

### Echo Pyramid voice unavailable

Verify:

* Echo Pyramid network reachability;
* TCP voice port configuration;
* `ECHO_PYRAMID_TTS_COMMAND`;
* WAV format: PCM, mono, 16 kHz and 16-bit.
